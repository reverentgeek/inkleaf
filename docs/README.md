# Inkleaf Docs

Two very different kinds of document live in here, so mind the labels. The first group describes reality. The second group is daydreaming.

## How the app works today

Accurate descriptions of code that actually exists:

- [save-note.md](save-note.md): end-to-end walkthrough of editing a note, from keystrokes through to Atlas and async embedding generation
- [semantic-search.md](semantic-search.md): end-to-end walkthrough of a semantic search, from `Cmd+Shift+K` through embeddings to `$vectorSearch`
- [project-structure.md](project-structure.md): quick tour of how the backend and frontend are laid out

## Possible future ideas

Exploratory sketches. **None of this is planned, scheduled, or committed.** They're thinking-out-loud documents about directions Inkleaf could take, kept around because the reasoning might be useful to someone. Nothing here is built.

- [future-features.md](future-features.md): scratch list of feature ideas
- [hosted-api-refactor-plan.md](hosted-api-refactor-plan.md): what it would take to split the backend into a hosted API plus a local offline agent
- [multi-tenant-saas-plan.md](multi-tenant-saas-plan.md): what multi-tenancy would demand. There's no hosted Inkleaf service, and none is intended.
- [cross-platform-architecture.md](cross-platform-architecture.md): candidate approaches for running somewhere other than the macOS desktop
